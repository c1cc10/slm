Agente Domotica

Documento di progetto · v0.1 · 2026-09-29

01 Il task più semplice dell'intero set

Il controllo domotico è il caso con lo spazio dei comandi più ristretto tra tutti i case study analizzati. I verbi di azione sono sei: accendi, spegni, alza, abbassa, imposta, dimmi. Le categorie di dispositivi sono una decina. Il modello non deve ragionare: deve riconoscere un intent da una frase breve e produrre un JSON strutturato.

A differenza degli assistenti virtuali commerciali (Alexa, Google Home, Siri) che gestiscono milioni di device generici in inglese, un SLM 45M addestrato su questa casa specifica conosce la lampada del corridoio, la tapparella del bagno padronale, il termostato studio — i nomi esatti dei dispositivi installati, non categorie generiche.

Vantaggio strutturale del modello piccolo Il corpus di training è l'elenco dei propri dispositivi (decine, non milioni). Un modello addestrato specificamente su questi nomi ha un vocabolario che coincide quasi perfettamente con il dominio reale. Zero long tail, zero ambiguità cross-domain. Alexa non saprà mai che "il salottino" è diverso da "il salotto" nella tua casa.

04 Vincoli e rischi

Questo è il caso con i vincoli più leggeri dell'intero set. Non ci sono dati personali sensibili (gli stati dei dispositivi non sono PII), non ci sono obblighi compliance, non ci sono safety-critical decisions. Il livello di rischio di un comando errato è basso: se il modello accende la luce sbagliata, l'utente la spegne.

Unico rischio reale: comandi irreversibili Alcuni comandi hanno conseguenze non banali: aprire la serratura del portone, disabilitare un allarme, accendere una stufa senza nessuno in casa. Per questi, l'orchestrator deve richiedere conferma esplicita indipendentemente da quanto sia sicuro il parsing del LM.
Privacy minimale Gli stati dei dispositivi (luce accesa/spenta, temperatura) non sono dati personali sensibili. L'unico dato da proteggere sono le automazioni che rivelano pattern di presenza/assenza (sicurezza abitazione). On-device consigliato ma non obbligatorio.

05 Dataset SFT

Il dataset è piccolo per definizione: lo spazio dei comandi è finito. Con 100–150 esempi annotati, il modello copre il 95% delle frasi reali.

// Comando semplice
{
  "input": "accendi la lampada del comodino",
  "output": [{"action": "turn_on", "device": "lampada_comodino"}]
}

// Comando multiplo con valore
{
  "input": "metti il termostato a 21 e accendi le luci del corridoio",
  "output": [
    {"action": "set_value", "device": "termostato_salotto", "value": 21, "unit": "°C"},
    {"action": "turn_on", "device": "luci_corridoio"}
  ]
}

// Query di stato
{
  "input": "com'è la temperatura in sala?",
  "output": {"action": "query_state", "device": "termostato_sala", "attribute": "temperature"}
}

// Condizionale
{
  "input": "quando esco di casa spegni tutto",
  "output": {"action": "create_automation", "trigger": "geofence_exit", "actions": [{"action": "turn_off", "device": "all"}]}
}

// Risposta da stato API (NLG)
{
  "input": {"device": "termostato_sala", "temperature": 19.5, "target": 21.0, "mode": "heating"},
  "output": "In sala ci sono 19,5 gradi. Il termostato sta salendo verso i 21 che hai impostato."
}

06 Integrazione con Home Assistant

Home Assistant espone un'API REST completa e un WebSocket per la gestione degli stati in tempo reale. Il layer Python è minimo: autenticazione con token, chiamata POST /api/services/light/turn_on, gestione risposta.

Per MQTT diretto (senza Home Assistant), il pattern è ancora più semplice: il JSON estratto dal LM viene serializzato e pubblicato sul topic corretto. Molti dispositivi smart home espongono già un'interfaccia MQTT nativa (Zigbee2MQTT, Tasmota, Shelly).

08 Raccomandazione

Il caso domotica è il più rapido da implementare dell'intero portfolio: dataset piccolo, nessun compliance, infrastruttura già esistente per chi usa Home Assistant. Il SFT può essere fatto come mini-run (50–100 step) in parallelo al Run #5 senza impatto sul training principale.

Priorità: alta · Costo: basso 100–150 esempi, mini-SFT su base moto o base wikipedia. Deployment: processo Python con chiamate HA API, avviabile in meno di una settimana se Home Assistant è già configurato. Il caso domotica è il candidato ideale come primo progetto end-to-end completo: dall'input NL all'azione fisica.
